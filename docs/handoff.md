# Lockkliye: handoff notes

## 1. The project

- Workspace root: `/home/burak/arsonite` with the folders `lockkliye` (the notes app), `teatype` (shared libraries and the HSDB database), `clover`, `quickle`, `snooPy`. Data of the backend: `LOCKKLIYE_DATA_PATH` of `.env` (`/var/lib/lockkliye`, created by `scripts/install`).
- Lockkliye: React 19, Vite 5, TypeScript 5.6, SCSS. Word-level formatted notes, offline first, saved to a FastAPI/HSDB backend with Ctrl+S.
- Shared UI lives in `teatype/ts/components` and is imported as `@teatype/components` (alias to `../teatype/ts`). Icons from `@teatype/icons`.

- Backend start: `teatype/teatype-venv/bin/python lockkliye/lockkliye_server.py` (default port 8765). The models are loaded at start, so changing a model needs a backend restart.
- Models: `Folder`, `Note`, `Settings`, `Block`, `Word`, `BlockPreset`, `NoteHistory`. `Settings` is a single row with `confirm_deletions`, `editor_width`, `light_mode`, `palette` (JSON text), `rev`, `show_block_borders` (optional bool), `sidebar_expanded`. Block style fields are columns (shared base class `BlockStyleFields`); history snapshot is one JSON column.

## 2. Architecture worth knowing

- **Local data**: IndexedDB `lockkliye` / store `kv`, keys `data | history | redo | sync`, loaded before the app renders (`NotesApp` returns null until then). There is no localStorage migration (removed on purpose, the first version ships when it is production ready). Only the sidebar's folder open/closed state is in localStorage (`lockkliye-folders-collapsed`).
- **Sync** (`client/sync/*`): the server generates entry ids; the engine keeps local key to server id in the `synced` meta and swaps `relations` at the boundary. `toRow()` must produce the same key order every time (its JSON is hashed to detect changes). A null relation payload clears an optional relation. Self-relation collections (folders) are pushed parents first, one at a time. A failed sync still commits the rows it created or deleted (`pushedKeys` / `removedKeys`), otherwise cleared history came back.
- **Settings sync**: `iSettingsItem` in `collections.ts` holds `lightMode, sidebarExpanded, editorWidth, confirmDeletions, showBlockBorders, palette`; `useSync.ts` `settingsOf` and its dependency list must contain every field, and a pulled settings row is merged with `Object.assign` into the state.
- **Settings page**: `SettingsView.tsx` builds a config for `TeaSettingsPage` (teatype, reusable, data driven: categories, groups, items; controls toggle/slider/select/button/buttons/custom; `developer: true` marks developer categories, groups or items with a badge; item `layout: 'stacked'` puts a wide control under its text). Categories: Appearance, Editor, Colors, Data, Developer.
- **Palette** (`client/tools/palette.ts`, `PaletteEditor.tsx`): three kinds, `text` (toolbar colors), `block` (block background colors), `gradient`. Built-in catalogs (about 30 text colors, 30 block colors, 20 gradients). At most 8 enabled per kind (`MAX_ENABLED`); user custom entries can be added and deleted (not edited) in Settings > Colors. State field `palette: { text|block|gradient: { enabled: string[], custom: string[] } }`. Defaults swap pink for gray. The per-block "add custom color" in the style menu is a different feature and is untouched (`customColor` / `customGradient` on the block).
- **Toolbar** (`FloatingToolbar.tsx`): colors show as a second bar only while Text color or Highlight mode is active. Holding Ctrl shows the letters of the Ctrl+key shortcuts under their buttons; adding Shift shows the Ctrl+Shift ones; Ctrl+Alt shows the size list with numbers. The blur of the bar is on a `::before` layer because an element with `backdrop-filter` is a backdrop root and its menus could not blur the note.
- **Shortcuts** (`SHORTCUTS` in `types/index.ts`, handler `useKeyboardShortcuts.ts`): Ctrl+B/I/U, Ctrl+Shift+S strikethrough, Ctrl+Shift+C color, Ctrl+Shift+H highlight, Ctrl+Shift+A anchor mode (picks the first anchor note if none chosen, logic in store `toggleFormatMode`), Ctrl+Alt+1..6 = Title, Heading, Subheading, Body, Small, Caption (digits are read from `e.code`), Ctrl+] and Ctrl+[ larger/smaller, Ctrl+S save, Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z undo/redo, Escape clears the mode and closes settings. Hyperlinks are switched off with `HYPERLINKS_ENABLED = false` in `types/index.ts`.
- **Block drag and drop** (`NoteEditor.tsx`): mouse based, not HTML5 drag. The ghost follows the mouse through `style.translate` on a ref (no re-render per move). The target slot is computed from block heights (not from rects, which are shifted by the move animation); a swap needs the cursor to pass the midpoint of the neighbour. `react-flip-toolkit` animates with `translate` only (no scale) and a flip key made of the visual block ids. The placeholder and the ghost are sized from the `.text-block` (width, height, margins), not from the row.
- **Block buttons / handle**: style, add above, add below, delete (32 px) and the drag handle are vertically centered on the block; blocks with a title get a different offset for the handle (`:has(.text-block--has-title)`). Buttons of a block you are not hovering have `pointer-events: none` so they do not cover the neighbour's buttons. Right-click on a block opens the style menu at the mouse, clamped into the window. Double-click on the width resize handle removes `widthPercent` (back to full width). New blocks (button, Shift+Enter, presets) scroll into view and get focus.
- **Setting "Outline blocks on hover"**: class `note-editor--block-borders`; dashed outline on `.text-block` while its row is hovered; no transition (`transition: all ..., outline 0s, outline-offset 0s`). Colour is in `editor.scss` (`color-mix` was introduced by the user).
- **Light mode for portaled UI**: the toast and TeaModal render in `document.body`, outside `.notes-app`. `NotesApp` toggles `light-mode` on `document.body`; `lightmode.scss` has a mixin `light-theme-vars` used by `.notes-app.light-mode` and by `body.light-mode .tea-toast-container, body.light-mode .tea-modal-overlay` (white surface, dark text).
- **Toast timer** (teatype `TeaToast`): an SVG rect outline with `pathLength=100`, so it runs at constant speed around the rounded corners; the container no longer clips overflow.
- **Scrollbars**: teatype `TeaApp.scss` mixin sets `scrollbar-width/color` on `*`; Chrome then ignores `::-webkit-scrollbar` styles and draws a native scrollbar WITH arrows. The thumb colour comes from `--scrollbar-thumb` which Lockkliye defines in `vars.scss` (30% white) and `lightmode.scss` (30% black). A previous attempt to remove the arrows (use webkit rules, hide `::-webkit-scrollbar-button`, themed thumb colours in `editor.scss`, `sidebar.scss`, `TeaSidebar.scss`) was reverted on request. Removing the arrows is still open if wanted (see section 5).
- **Spaces in blocks**: `RichTextEditor.parseHTMLToWords` keeps the spaces before the first and after the last word as part of those words' text (words are otherwise joined by single spaces). Tested by reload.
- **Folders**: nested folders via self relation `Folder.parent`; folder colors were removed (UI and dot); the stored `color` field still exists in data and sync.
- **Sidebar**: the not-saved dot sits left of the note title; the title has padding with negative margin so the dot glow is not clipped by the ellipsis overflow.

## 3. How to run and test safely

- Dev server: `cd lockkliye && VITE_HSDB_PORT=8766 ./node_modules/.bin/vite --port 3010` (run from the lockkliye dir; the eslint plugin needs the cwd).
- IMPORTANT: the default `LOCKKLIYE_PORT` is 8765, the user's real, running backend (a test page then shows the user's own notes). Always start test servers with `LOCKKLIYE_PORT=8766` (nothing listens there, the app works offline) or start a test backend with a temporary data path (`mkdir /tmp/lk && LOCKKLIYE_DATA_PATH=/tmp/lk LOCKKLIYE_PORT=8766 <teatype venv>/bin/python lockkliye_server.py`). A test Ctrl+S against 8765 writes real data. After a test: `find /var/lib/lockkliye -type f -mmin -5` should only show the user's own activity. Each test dev-server port is a new browser origin with its own IndexedDB.
- Type-check: `node_modules/.bin/tsc -p tsconfig.app.json --noEmit 2>&1 | grep -E "^client/|^index"`. Baseline warnings: unused `saveCursorPosition` / `restoreCursorPosition` in `RichTextEditor.tsx`. ESLint: `node_modules/.bin/eslint client` (about 12 warnings, 0 errors). SCSS check: `node_modules/.bin/sass --load-path=client/style --quiet client/style/index.scss > /dev/null`.
- Browser tool quirks: tabs are often hidden (requestAnimationFrame and smooth scroll paused, screenshots can be stale, use selector screenshots); real Ctrl keys are not delivered (dispatch `KeyboardEvent`); use `document.execCommand('insertText')` to type; page ids expire quickly (reopen with 127.0.0.1); Playwright snippets have no `Buffer`.
- Tool quirks: `multi_replace_string_in_file` checks uniqueness against the original file; `get_errors` can show stale results right after an edit.

## 6. Notes the assistant kept for this repo (memory file)

- HSDB overview doc: `teatype/py/teatype/db/hsdb/README.md`; API `from teatype.modulo.hsdb import hsdb`, `hsdb.init(name, models, ...)`; client `HSDBClient.py`.
- `from teatype.db.hsdb import X` inside core/indices during package init yields the submodule (import cycle): import lazily from the submodule path.
- `ApplicationUnit`: use `.create(**kw)`; hijacks SIGINT; non-daemon backend thread; pass `include_*=False` to embed.
- PATCH `null` unsets an optional relation (`HSDBModel.update` + `RelationalIndex.discard`); `Folder.parent = HSDBRelation.ManyToOne(Folder)` is assigned after the class body.
- Disk persistence restores (HybridStorage.restore, incl. relations); cold_mode plus create needs `write=False`.
- `grep_search` with broad include patterns and alternation can time out in monorepos: scope the include pattern. If the workspace is a network mount, fall back to terminal grep and do not trust a surprising empty broad result.
